## 6. 2D Motion Graphics

### 6.1 Planar Elements, Shapes, Strokes, Curves, Masks, and Track Mattes

Definition: Parametric 2D vector primitives (rectangles, ellipses, polygons, cubic Bézier splines) and stencil/alpha masking hierarchies positioned on `+X/+Y` planar cards (`camera looks -Z`) ([Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F)).
Why:

- Emotion: Sharp geometric polygons and mitered strokes project crisp technological precision; rounded caps, joins, and organic Bézier curves project approachable warmth ([Block, The Visual Story](https://www.google.com/search?q=https%3A%2F%2Fwww.routledge.com%2FThe-Visual-Story-Creating-the-Visual-Structure-of-Film-TV-and-Digital-Media%2FBlock%2Fp%2Fbook%2F9781138014152)).
- Attention: Animated masks and track mattes create localized windows of discovery, guiding the eye inside bounded graphic containers.
- Production value: Maintaining constant world-space stroke width during non-uniform container scaling separates professional procedural vector work from stretched bitmap scaling.
- Clarity: Clean boolean masks and alpha/luma mattes isolate overlapping graphic layers without messy overlapping contours.
- Cost: Parametric vector shapes and stencil/alpha mattes render at negligible vertex/fragment cost compared to full-frame bitmap sequences.
  Rules:

1. Decouple **Stroke Width** from non-uniform parent scale transforms (`non_scaling_stroke = true`): when a rectangular card scales from `(1.0, 1.0)` to `(2.5, 0.4)`, its border stroke must remain a uniform pixel width (`e.g., 3.0 px` or `0.28% H`) on both horizontal and vertical edges ([Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F)).
2. Enforce **Concentric Corner Radius Math**: when nesting a rounded rectangle with inner padding $P$ inside an outer rounded container of radius $R_{\text{outer}}$, set the inner corner radius to $R_{\text{inner}} = \max(0,\; R_{\text{outer}} - P)$ so the Negative Space gap maintains uniform radial thickness around the corner arc `[OPINION]`.
3. Choose **Masking vs. Track Matte** architecture explicitly:
   - **Element-Local Mask**: Bézier path bound to the element's local transform coordinate space (moves with the element).
   - **Independent Track Matte (Alpha or Luma Matte)**: Stationary or independently animated stencil planar element in parent/world space through which the target element passes (`alpha_matte` uses the stencil's coverage channel $A$; `luma_matte` uses the stencil's BT.709 luminance $Y = 0.2126R + 0.7152G + 0.0722B$) ([Adobe After Effects Help](https://www.google.com/search?q=https%3A%2F%2Fhelpx.adobe.com%2Fafter-effects%2Fdesktop.html); [Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F)).
4. Set miter limits on sharp-angled strokes to `miter_limit = 4.0` (automatically converting angles `< 29°` to bevel joins) or use `round` joins/caps to prevent infinitely spiking stroke vertices during acute path deformations ([Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F)).
   Event mapping: Declarative `planar_shape_element(geometry="bezier_spline"|"rounded_rect", stroke_width_px, cap="round"|"butt", join="round"|"miter", matte_source_id, matte_mode="alpha"|"luma")` driven by transform and path-parameter events.
   Raster/bake note: Render 2D vector splines on the GPU using either hardware MSAA (`4×–8×`) on loop-Blinn / stencil-then-cover triangulated meshes or analytic Signed Distance Field (SDF) fragment shaders (`smoothstep(-0.7px, +0.7px, sdf_dist)`) for sub-pixel anti-aliasing.
   Cultural notes: Flat vector motion graphics ("corporate Memphis" vs. geometric Swiss motion) dominate SaaS and explainer media; combining textured luma mattes (ink bleeds, halftone screens, paper grain) with crisp vector geometry bridges digital precision and tactile analog craft `[OPINION]`.
   Failure modes: Scaling a stroked rectangle non-uniformly without `non_scaling_stroke` → vertical borders become thick bars while horizontal borders vanish; setting $R_{\text{inner}} = R_{\text{outer}}$ on nested cards → corners look pinched and non-parallel.
   Checklist: [ ] `non_scaling_stroke` enabled on non-uniformly scaled shapes [ ] Nested corner radii follow $R_{\text{inner}} = \max(0, R_{\text{outer}} - P)$ [ ] Miter limit capped at `4.0` or round joins used [ ] Track mattes used for world-space reveals; local masks for element-locked crops
   Sources: [Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F); [Block, The Visual Story](https://www.google.com/search?q=https%3A%2F%2Fwww.routledge.com%2FThe-Visual-Story-Creating-the-Visual-Structure-of-Film-TV-and-Digital-Media%2FBlock%2Fp%2Fbook%2F9781138014152); [Adobe After Effects Help](https://www.google.com/search?q=https%3A%2F%2Fhelpx.adobe.com%2Fafter-effects%2Fdesktop.html).

### 6.2 Path Animation, Trim Operations, and Topological Morphing

Definition: The continuous parametric evaluation of stroke arc-length intervals (`trim_start`, `trim_end`, `trim_offset`), motion along a spline (`orient_along_path`), and vertex-to-vertex interpolation between two closed or open Bézier topologies (morphing) ([Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F)).
Why:

- Emotion: Fluid trim-path tracers and seamless topological morphs create a sense of magic, continuity, and effortless kinetic flow.
- Attention: The leading tip of an animated trim path acts as a moving laser pointer that pulls the viewer's eye directly to the next focal node.
- Production value: Arc-length-parameterized speed and matched vertex winding prevent the pulsing velocity and inside-out self-intersecting twists of amateur path morphs.
- Clarity: Connects cause-and-effect nodes across diagrams, maps, and icon state changes without cutting.
- Cost: Analytic Bézier vertex interpolation on planar splines achieves fluid shape transformation at `< 1%` of the cost of 3D mesh booleans.
  Rules:

1. Reparameterize all motion paths and trim strokes by **Normalized Arc Length ($s \in [0.0, 1.0]$)** rather than raw Bézier parameter $t \in [0.0, 1.0]$ (using a `64–128` entry arc-length lookup table per cubic segment) so an element traveling at constant event speed does not suddenly speed up on long segments and stall at clustered control points `[OPINION]`.
2. For **Traveling Line / Tracer Effects** (`trim_start` chasing `trim_end`), stagger the `trim_end` event (`start = t₀`, `ease = cubic_in_out`, `duration = 16–30 frames`) ahead of the `trim_start` event (`start = t₀ + 4–10 frames`, `ease = cubic_in_out`, `duration = 16–30 frames`) so the line stretches out at peak velocity in the middle of the path and contracts smoothly to `0%` length at the destination ([Williams, The Animator's Survival Kit](https://www.google.com/search?q=https%3A%2F%2Fen.wikipedia.org%2Fwiki%2FThe_Animator%2527s_Survival_Kit); [Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F)).
3. Enforce the **Three Laws of Topological Morphing** between Shape A and Shape B:
   - **Equal Vertex Count ($N_A = N_B$)**: Subdivide whichever spline has fewer cubic Bézier knots using De Casteljau's algorithm at matching normalized arc-length ratios before interpolating.
   - **Matched First Vertex (`index = 0`)**: Align the starting knot `v₀` of both shapes to the same topological compass quadrant (e.g., top-most vertex at `12 o'clock`) so vertices travel the shortest straight path rather than rotating around the perimeter.
   - **Matched Winding Order**: Both splines must wind in the exact same direction (`clockwise` → `clockwise` or `counter-clockwise` → `counter-clockwise`) ([Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F)).
4. Add a `10%–20%` **Anticipation / Overshoot Scale or Squash-and-Stretch** event across the midpoint (`t = 0.5`) of a 2D shape morph (`duration = 10–18 frames`) so the intermediate state reads as an energetic physical transformation rather than a stiff linear vertex crossfade ([Thomas \& Johnston, The Illusion of Life](https://www.google.com/search?q=https%3A%2F%2Fwww.penguinrandomhouse.com%2Fbooks%2F727679%2Fillusion-of-life-the-by-frank-thomas%2F)).
   Event mapping:

- Trim: `trim_event(target_curve_id, channel="trim_end", start=t0, duration=20f, from=0.0, to=1.0, easing="cubic_in_out")` + `trim_event(target_curve_id, channel="trim_start", start=t0+6f, duration=20f, from=0.0, to=1.0, easing="cubic_in_out")`.
- Morph: `morph_event(target_spline_id, from_topology="shape_a", to_topology="shape_b", start=t0, duration=14f, easing="expo_in_out")`.
  Raster/bake note: Pre-normalize spline topologies (`N` vertices, aligned `v₀`, uniform winding) during scene compilation/baking so runtime vertex shaders only execute a fast linear/eased `mix(pos_A, pos_B, u_morph)` per vertex.
  Cultural notes: Liquid-motion 2D frame-by-frame and spline morphing (popularized by European and North American boutique motion studios) uses trailing secondary smear shapes (`2–4 frame` delayed echo paths) to bridge distant screen coordinates `[OPINION]`.
  Failure modes: Morphing two closed paths with opposite winding orders or mismatched `v₀` indices → the shape collapses through its own center into an hourglass self-intersection at `t = 0.5`; animating `trim_start` and `trim_end` with identical start times and durations → rigid worm of fixed length sliding mechanically along the path.
  Checklist: [ ] Motion/trim paths parameterized by normalized arc length $s$ [ ] Trim-start lags trim-end by `4–10 frames` for organic stretch/contract [ ] Morphing shapes share equal vertex count, aligned `v₀`, and identical winding [ ] Midpoint morph softened with anticipation/overshoot scale event
  Sources: [Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F); [Thomas \& Johnston, The Illusion of Life](https://www.google.com/search?q=https%3A%2F%2Fwww.penguinrandomhouse.com%2Fbooks%2F727679%2Fillusion-of-life-the-by-frank-thomas%2F); [Williams, The Animator's Survival Kit](https://www.google.com/search?q=https%3A%2F%2Fen.wikipedia.org%2Fwiki%2FThe_Animator%2527s_Survival_Kit).

### 6.3 2D Transitions (Cut, Dissolve, Wipe, Push, Slide, Zoom, Morph, Mask Reveal, Luma, Whip)

Definition: The spatial, optical, or geometric handoff mechanism bridging Outgoing Scene A and Incoming Scene B across a shared temporal window (`0` to `72 frames`).
Why:

- Emotion: Dictates the perceived weight of a scene boundary—from invisible narrative continuity (Cut) or wistful memory (Dissolve) to kinetic propulsion (Whip/Zoom/Mask Reveal).
- Attention: Motion-driven transitions carry the viewer's gaze vector directly across the boundary into the incoming focal anchor.
- Production value: Motivated, speed-matched transitions with continuous velocity across the midpoint read as seamless cinematography, whereas unmotivated stock wipes read as amateur slideshow templates.
- Clarity: Signals to the viewer whether time, location, or conceptual hierarchy has changed.
- Cost: Shader-based luma mattes, pushes, and whip-pans execute in real time at zero extra scene geometry cost.
  Rules:

1. Follow the **2D Transition Parameter & Motivation Specification**:

| Transition Type               | Duration Range (@ `24–30 fps`) | Easing / Velocity Profile                                                                   | Mandatory Motivation & Execution Rule                                                                                                                                                                                         |
| :---------------------------- | :----------------------------- | :------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hard Cut**                  | `0 frames`                     | Instantaneous step                                                                          | Default for `≥ 85%` of all transitions; match action or eye-trace (`Δpos ≤ 15% W`) ([Murch](https://www.google.com/search?q=https%3A%2F%2Fen.wikipedia.org%2Fwiki%2FIn_the_Blink_of_an_Eye_%28Murch_book%29)).                |
| **Dissolve**                  | `24–72 frames` (`1.0–3.0 s`)   | `sine_in_out` or `linear` in **Linear Light**                                               | Signals passage of time or thematic overlap; never use `6–12 frame` "soft cuts" solely to hide a bad edit `[OPINION]`.                                                                                                        |
| **Wipe (Geometric)**          | `12–24 frames` (`0.5–1.0 s`)   | `cubic_in_out` with `2–4 frame` multi-layer stagger                                         | Edge must be angled (`15°–75°`) or multi-layered (2–3 offset color bands staggered by `2–3 frames`); avoid raw unfeathered single-line vertical wipes `[OPINION]`.                                                            |
| **Push / Slide**              | `10–20 frames` (`0.4–0.8 s`)   | `expo_in_out` or `cubic_in_out`                                                             | Incoming scene pushes outgoing scene (Push) or slides over a `20%–40%` parallax-retarded outgoing scene (Slide); align direction with subject reading vector.                                                                 |
| **Zoom (Scale-Through)**      | `10–18 frames` (`0.4–0.75 s`)  | Exponential scale $S(t) = S_0 \cdot e^{kt}$ (`expo_in` → cut at peak velocity → `expo_out`) | Scale must be **logarithmic/exponential** (`e.g., 1.0× → 8.0×` in Shot A matched to `0.125× → 1.0×` in Shot B at the midpoint cut) with radial motion blur; linear scale creates a visible speed kink at the cut `[OPINION]`. |
| **Morph Transition**          | `12–24 frames` (`0.5–1.0 s`)   | `cubic_in_out`                                                                              | Hero silhouette of Shot A transforms topologically into hero silhouette of Shot B while backgrounds cross-dissolve or wipe.                                                                                                   |
| **Mask Reveal (Object Wipe)** | `12–30 frames` (`0.5–1.25 s`)  | Matched to foreground occluder velocity                                                     | A foreground element (pillar, character back, graphic card) traverses `100%` of the frame width; clip Shot B to the trailing edge of the occluder.                                                                            |
| **Luma Matte (Gradient/Ink)** | `18–36 frames` (`0.75–1.5 s`)  | `cubic_in_out` on threshold $T \in [-f, 1+f]$                                               | Drive alpha via `smoothstep(T - feather, T + feather, luma_map)` with `feather ∈ [0.05, 0.20]` so high-luminance (or low-luminance) areas transition organically first.                                                       |
| **Whip (Swish Pan/Tilt)**     | `6–12 frames` (`0.25–0.5 s`)   | `cubic_in` (Shot A) → cut at max velocity (`≥ 25% W/frame`) → `cubic_out` (Shot B)          | Apply directional vector blur (`shutter_angle = 180°–360°`) + mirrored edge tile/wrap at the midpoint frame so seam is completely invisible.                                                                                  |

2. Enforce **Midpoint Velocity Continuity ($C^1$ Velocity Match)** on all Push, Slide, Zoom, and Whip transitions: the instantaneous velocity at the final frame of Outgoing Shot A must equal the instantaneous velocity at the first frame of Incoming Shot B (`v_out(t_cut) == v_in(t_cut)`). Stopping at the midpoint (`ease_in_out` on Shot A followed by `ease_in_out` on Shot B) creates a double-clutch stutter.
   Event mapping: Dual-scene transition event `scene_transition_event(from_scene_id, to_scene_id, type="whip"|"zoom"|"luma"|"mask_reveal", start_frame, duration_frames, direction_vec, easing="expo_in_out")` that schedules outgoing and incoming camera/compositor transforms across the overlap window.
   Raster/bake note: During transition overlap windows (`duration_frames`), render both Scene A and Scene B into off-screen `fp16` color targets (or evaluate Scene B in a single-pass stencil/luma composite when geometry allows) and execute directional/radial motion blur + linear-light blending in the composite shader.
   Cultural notes: Kurosawa and classic adventure cinema (_Star Wars_) use deliberate directional Wipes as narrative chapter markers; Edgar Wright-style kinetic editing uses `6–10 frame` Whip Pans and Object Mask Reveals to compress mundane transitions into rhythmic comedy beats `[OPINION]`.
   Failure modes: Using linear scale (`scale = mix(1.0, 10.0, t)`) on a Zoom transition → the zoom appears to rush violently at the beginning and crawl at the end because perceived optical magnification is proportional to $\Delta S / S$; chaining a Zoom transition into a Whip transition into a Spin transition within `5 seconds` → viewer motion sickness and amateur "preset pack" fatigue.
   Checklist: [ ] Hard Cuts account for `≥ 85%` of edits [ ] Dissolves blended in linear light (`≥ 24 frames`) [ ] Zoom transitions use exponential scale $S(t) = S_0 e^{kt}$ [ ] Whip/Push/Zoom velocity is continuous ($C^1$) across the midpoint cut [ ] Zero consecutive unmotivated stylized transitions
   Sources: [Murch, In the Blink of an Eye](https://www.google.com/search?q=https%3A%2F%2Fen.wikipedia.org%2Fwiki%2FIn_the_Blink_of_an_Eye_%28Murch_book%29); [Mascelli, The Five C's of Cinematography](https://www.google.com/search?q=https%3A%2F%2Fwww.silmanjamespress.com%2Fshop%2Ffilmmaking-directing%2Fthe-five-cs-of-cinematography%2F); [Lottie v1.0 Specification](https://www.google.com/search?q=https%3A%2F%2Flottie.github.io%2Flottie-spec%2F1.0%2F).
