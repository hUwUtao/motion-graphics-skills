## 5. Color Pipeline

### 5.1 Scene-Referred vs. Display-Referred Linear Workflow and ACES/OCIO Concepts

Definition: A deterministic end-to-end color management architecture that converts all input assets via Input Transforms (IDTs) into a wide-gamut, scene-linear working space (`[0, +∞)`) for physically plausible lighting, blurring, and compositing, and maps the result to the target display via an Output Transform (RRT + ODT) ([ACES Documentation](https://www.google.com/search?q=https%3A%2F%2Fdocs.acescentral.com%2F); [OpenColorIO Documentation](https://www.google.com/search?q=https%3A%2F%2Fopencolorio.readthedocs.io%2Fprojects%2Fconfig-aces%2Fen%2Flatest%2F)).
Why:

- Emotion: Preserves natural highlight roll-off (desaturating smoothly toward white like photochemical film) rather than harsh digital channel clipping that feels cheap and video-like.
- Attention: Keeps specular highlights, light blooms, and defocus bokeh luminous and physically compelling.
- Production value: Eliminates dark halos around alpha-composited edges, pinched clipped highlights, and incorrect motion-blur trails caused by gamma-encoded math.
- Clarity: Ensures an asset's material color looks consistent regardless of lighting exposure or target delivery display (`sRGB`, `BT.709`, `Display P3`, or `BT.2100 HDR`).
- Cost: Using a declarative [OpenColorIO (OCIO)](https://www.google.com/search?q=https%3A%2F%2Fopencolorio.readthedocs.io%2Fprojects%2Fconfig-aces%2Fen%2Flatest%2F) configuration automates all color conversions across 2D, 3D, and compositing stages with zero manual per-shot gamma hacks.
  Rules:

1. Strictly separate **Scene-Referred Linear Data** (radiometric light ratios in `[0.0, +∞)`, middle gray `18%` reflectance = `0.18`, no upper clamp at `1.0`) from **Display-Referred Nonlinear Data** (transfer-function-encoded pixel values bounded to `[0.0, 1.0]` representing emitted monitor luminance) ([ACES Documentation](https://www.google.com/search?q=https%3A%2F%2Fdocs.acescentral.com%2F)).
2. Configure the pipeline around the four canonical [ACES / OpenColorIO](https://www.google.com/search?q=https%3A%2F%2Fopencolorio.readthedocs.io%2Fprojects%2Fconfig-aces%2Fen%2Flatest%2F) stages:
   - **Input Transform (IDT)**: Linearizes 8-bit/16-bit display-referred textures (e.g., removing the sRGB piecewise EOTF $\approx x^{2.2}$) into the working space for albedo/color maps, while marking data maps (`normal`, `roughness`, `metallic`, `displacement`, `ao`) as **`Raw / Non-Color Data`** (zero gamma transform).
   - **Working Space**: Execute all 3D shading, lightmap baking, alpha compositing, defocus blur, and motion blur in **Scene-Linear RGB**—either `Linear Rec.709 / sRGB` for standard-gamut projects or **`ACEScg` (AP1 primaries, linear transfer)** for wide-gamut studio pipelines ([ACES Documentation](https://www.google.com/search?q=https%3A%2F%2Fdocs.acescentral.com%2F)).
   - **Look Modification Transform (LMT)**: Apply creative scene-referred grading in linear or log (`ACEScct`) space before tone mapping.
   - **Output Transform (RRT + ODT)**: Map unbounded scene-linear `[0.0, +∞)` through a sigmoid filmic tone mapper (Reference Rendering Transform) and encode to the specific display's gamut and inverse EOTF (Output Device Transform).
3. **Graphic / Brand Hex Color Exception**: When a brief mandates an exact display-referred brand hex code (e.g., `#FF3B30`) on a flat 2D UI or logo element, either composite that 2D layer _after_ the 3D scene's RRT/ODT tone-mapping pass OR apply an **Inverse Output Transform (Inverse ODT)** to the swatch so that after passing through the RRT/ODT it measures within $\Delta E_{00} \le 1.0$ of the brand hex code (`[OPINION]`; sources conflict between pure scene-referred purists who accept tone-mapped desaturation of bright logos and commercial broadcast specs that require exact brand hex match—**recommend**: composite flat 2D brand logos/UI in display-referred linear space post-tone-mapping, and use scene-referred shading for 3D integrated elements).
   Event mapping: Scene configuration block `color_pipeline(ocio_config="aces_v2", working_space="ACEScg"|"linear_rec709", view_transform="ACES_1.3_SDR_Video"|"AgX", display_space="Rec.709"|"sRGB"|"Display_P3")`.
   Raster/bake note: All framebuffers and baked lightmaps in the GPU rasterizer must use floating-point formats (`R16G16B16A16_SFLOAT` or `R11G11B10_UFLOAT_PACK32` when no alpha is needed) so emissive surfaces and specular highlights (`intensity = 2.0–50.0`) drive physical bloom and motion blur before the final full-screen Output Transform pass.
   Cultural notes: High-end VFX and animation studios standardize on ACES (`ACES 1.3` / `ACES 2.0` via OCIO), while stylized 3D and game-engine raster pipelines frequently use `AgX` or `Filmic` tone mappers for smoother chromatic highlight desaturation.
   Failure modes: Forgetting to mark a Normal Map or Roughness Map as `Raw / Non-Color` → the pipeline applies an sRGB-to-Linear `2.2` curve to the normal vectors, causing all surface lighting directions to tilt and crease; blurring or alpha-over compositing in gamma-encoded sRGB → dark muddy fringes around glowing objects and dim, lifeless motion blur trails.
   Checklist: [ ] Working space is scene-linear (`ACEScg` or `Linear Rec.709`) in `fp16` buffers [ ] Albedo textures linearized via IDT; Normal/Roughness/Metallic marked `Raw` [ ] Blurs, alpha-overs, and light bakes executed in linear space [ ] Tone-mapping Output Transform applied once at the very end of the pipeline
   Sources: [ACES Official Documentation](https://www.google.com/search?q=https%3A%2F%2Fdocs.acescentral.com%2F); [OpenColorIO Configuration for ACES](https://www.google.com/search?q=https%3A%2F%2Fopencolorio.readthedocs.io%2Fprojects%2Fconfig-aces%2Fen%2Flatest%2F); [Vulkan Specification](https://www.google.com/search?q=https%3A%2F%2Fdocs.vulkan.org%2Fspec%2Flatest%2Findex.html).

### 5.2 Primary and Secondary Grading, LUTs, Tone Mapping, and Output Transforms

Definition: The mathematical manipulation of exposure, white balance, contrast, and isolated hue/luminance ranges (grading), combined with Lookup Tables (LUTs) and standard Output Transforms for SDR and HDR delivery targets.
Why:

- Emotion: Establishes the final atmospheric temperature, contrast tension, and tactile filmic cohesion across all shots.
- Attention: Uses secondary qualifiers and power windows/vignettes to subtly darken peripheral distractions by `0.3–0.8 stops` and elevate the subject.
- Production value: Proper log-space grading and tetrahedral 3D LUT interpolation prevent clipped shadows, solarized skin tones, and posterized skies.
- Clarity: Normalizes shot-to-shot brightness and color balance so cuts within a scene feel continuous.
- Cost: Executing primary/secondary grades as parametric shader uniforms and a single combined 3D LUT texture lookup runs in `< 0.05 ms` on the GPU.
  Rules:

1. Execute **Primary Grading** in a perceptually uniform Log or Scene-Linear working space before the Output Transform:
   - **Exposure (Linear Gain)** and **White Balance (Chromatic Adaptation)**: adjust in Scene-Linear space (`RGB_linear * 2^stops`).
   - **Lift / Gamma / Gain (or Offset / Power / Slope per ASC CDL)** and **S-Curve Contrast**: adjust in log working space (`ACEScct` or log intermediate working space) pivoting around middle gray (`0.18` linear $\approx 0.4135$ in `ACEScct`) ([ACES Documentation](https://www.google.com/search?q=https%3A%2F%2Fdocs.acescentral.com%2F); [DaVinci Resolve Manual](https://www.google.com/search?q=https%3A%2F%2Fdocuments.blackmagicdesign.com%2FUserManuals%2FDaVinci-Resolve-20-Beginners-Guide.pdf%3F_v%3D1757574013000)).
2. Constrain **Secondary Grading** (HSL/OKLCH qualifiers and spatial masks) with soft feather roll-offs (`Δh feather ≥ 15°`, `ΔL feather ≥ 0.08`, spatial mask feather `≥ 5%` of frame width); hard-edged color keys create visible tearing and chatter across animated frames.
3. Never feed unbounded scene-linear `[0.0, +∞)` values directly into a standard `[0.0, 1.0]` **3D LUT**: always sandwich a 3D LUT (`33×33×33` or `65×65×65` `.cube` with **tetrahedral interpolation**, never trilinear) inside a deterministic **Shaper Log Space** (`Linear -> Log Shaper -> 3D LUT -> Linear` or display output) so highlights above `1.0` are not hard-clipped upon entry ([OpenColorIO Documentation](https://www.google.com/search?q=https%3A%2F%2Fopencolorio.readthedocs.io%2Fprojects%2Fconfig-aces%2Fen%2Flatest%2F)).
4. Match the **Output Transform** and container metadata tags to the exact delivery specification:

Event mapping: Post-processing shader pass `grade_and_output_pass(exposure_ev, wb_temp, cdl_slope, cdl_offset, cdl_power, saturation_oklab, lut_3d_id, output_transform="BT709_2.4")`.
Raster/bake note: Bake the combined LMT + RRT + ODT chain into a single `65×65×65` 3D LUT preceded by an analytic `ACEScct` or `AgX Log` shaper function in the final full-screen fragment shader pass for single-instruction hardware texture evaluation.
Cultural notes: The display transfer-function tag mismatch ("1-1-1 vs. 1-2-1 gamma shift") (`1-1-1` vs. `1-2-1` NCLC tag mismatch) causes washed-out blacks on color-managed OS displays when exporting `BT.709` (`γ = 2.4`) without explicit `1-1-1` or `1-2-1` tagging; for multi-platform web social delivery (`YouTube`, `Instagram`, `TikTok`), grading at `γ = 2.2` (or `γ = 2.4` in a dim room with verified `1-1-1` tagging and black levels anchored at `IRE 1–2`) prevents lifted milky shadows `[OPINION]`.
Failure modes: Applying a `17×17×17` display-referred LUT with trilinear interpolation to a high-contrast grade → severe color banding and clipped neon highlights; placing graphics at `100%` peak white (`1,000 nits`) in an HDR `BT.2100 PQ` timeline instead of `203 nits` SDR reference white → subtitles and logos sear the viewer's eyes ([ITU-R Report BT.2390](https://www.google.com/search?q=https%3A%2F%2Fwww.itu.int%2Fdms_pub%2Fitu-r%2Fopb%2Frep%2FR-REP-BT.2390-8-2020-PDF-E.pdf)).
Checklist: [ ] Exposure/WB adjusted in linear; contrast/CDL adjusted in log around `0.18` pivot [ ] 3D LUTs are `≥ 33³` with tetrahedral interpolation and log shaper [ ] Secondary qualifiers feathered `≥ 15°` hue / `≥ 0.08` lightness [ ] Output NCLC tags (`1-1-1` for SDR BT.709) embedded in final stream [ ] HDR graphics anchored at `203 nits` diffuse white (PQ)
